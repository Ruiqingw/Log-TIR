# 01. Project Context

## 这是什么项目

`Log-TIR` 是一个面向 `Text-to-SQL` 的 agent 项目。

更具体地说，它希望训练一个模型完成下面这条链路：

1. 读懂自然语言问题
2. 生成 SQL
3. 在本地数据库中执行 SQL
4. 如果执行报错，或者结果不对，就根据错误信息继续改 SQL
5. 最后得到正确结果

这不是一个“只生成一条 SQL 就结束”的静态模型项目，而是一个带执行和自纠错闭环的 agent 项目。

## 为什么 Day 1 先做这两件事

Day 1 聚焦两个底层能力：

1. 安全地执行 SQL
2. 正确地判断 SQL 是否答对了问题

这两个能力分别由两个文件承担：

- `sandbox.py`
- `eval.py`

原因很简单：

- 如果不能安全执行 SQL，后面的训练和 rollout 都没有可信环境
- 如果不能正确评估答案是否正确，后面的 reward 就不可信

所以 Day 1 其实是在做“训练前的基础设施校准”。

## 项目里出现的几个关键词

第一次接手的人可能会被几个名词卡住。这里不展开讲理论，只给“够用版”解释。

`Text-to-SQL`
: 输入是自然语言问题，输出是 SQL 查询。

`Spider`
: 一个学术界常用的 Text-to-SQL 基准数据集。里面有很多数据库、问题和标准 SQL。

`Execution Match`
: 不看 SQL 写得像不像标准答案，而是看执行后的结果是否一致。

`GRPO`
: 一种强化学习训练方法。这里它是 Day 3 之后的事情，不是 Day 1 的重点。

`SFT`
: 监督微调。这里指先给模型看格式正确的示例，让它学会基本行为，再进入强化学习。

如果你对这些名词陌生，可以直接把它们发给 AI，让 AI 用“面向工程实现”的方式解释，而不是论文摘要式解释。

## 当前项目状态

截至 Day 1 结束，这个仓库已经具备：

- Spider 数据
- 可复用的 SQL sandbox
- 可复用的 execution-match evaluator
- 基本测试
- 实际运行记录

截至 Day 1 结束，这个仓库还没有具备：

- SFT 数据构造脚本
- 训练脚本
- rollout 轨迹格式定义
- GRPO 训练入口
- BIRD 数据接入

所以你应该把当前仓库理解成：

“训练前基础设施已经打底，但训练本身还没有开始。”
